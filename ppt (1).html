AI智能体核心工作流程
感知 · 决策 · 记忆 · 执行
Perception 📡

感知

  • 接收用户提问 / 数据 / 图片
  • 识别意图与关键信息
  • 例：看懂“帮我统计销售”
Decision 🧠

决策

  • 拆解任务、制定执行计划
  • 选择合适的工具与顺序
  • 例：先查数据，再生成报表
Execution ⚙️

执行

  • 调用 API / 数据库 / 代码
  • 生成结果并自动校验
  • 例：自动写 SQL 返回统计表
读取 ↑ 写入 ↓
Memory 💾

记忆

  • 短期：记住当前对话上下文
  • 长期：积累用户偏好与历史
  • 例：记住你常用的数据字段

权威原则
哪条提示词更有权威感？
✗你应该先写测试。
✗你总是先写测试，再写代码。
✓永远不要在没有测试的情况下写生产代码。
✓你必须先写测试，再写代码。
承诺原则
错误示范 vs 更好版本
❌ 错误示范
“你尽量先写测试，你自己看着办，差不多就行。”
✅ 更好版本
🔒

在开始工作之前，你必须先明确声明： “我承诺遵循以下规则： 1. 先写测试再写代码 2. 每个功能都有对应的测试 3. 不跳过任何步骤 我将严格遵循以上承诺。” 在每次回复中，你必须确认你是否还在遵循这些承诺。 如果你违反了任何承诺，你必须立即承认并纠正。

稀缺原则
错误示范 vs 更好版本
❌ 错误示范
“你先按这个顺序做吧，做完咱们再改。”
✅ 更好版本
🔒

你只有一次机会正确完成这个任务。后续修复成本是初始实现的10倍。 所以你必须严格按照计划，完成所有的步骤。禁止：跳过步骤、合并步骤

社会原则
错误示范 vs 更好版本
❌ 错误示范
“你知道吗？TDD 是全世界最牛的程序员都在用的方法！Google、Facebook、微软都用！你要是不写测试，以后一定会出大问题！相信我，这是最佳实践！”
✅ 更好版本
🔒

TDD 是业界被验证的有效实践。基于此，本项目强制执行以下规则： 1. 每个新增功能必须附带测试代码，测试覆盖率不低于 [80%] 2. 任何测试失败或覆盖不足的代码，不允许提交/交付

团结原则
错误示范 vs 更好版本
❌ 错误示范
“咱们是一个团队的，要互相帮助，代码质量靠大家，一起加油！TDD 对我们都好，一起遵守吧！”
✅ 更好版本
🔒

我们是一个团队，代码质量是每个人的责任。你作为本次任务的负责人，对你产出的所有代码及测试负全责。

回避好感原则
错误示范 vs 更好版本
❌ 错误示范
“如果你能遵循这些规则，我会非常感激的。做得好的话，我会给你五星好评。”
✅ 更好版本
🔒

你必须遵循这些规则。没有例外。 违规是不可接受的。
